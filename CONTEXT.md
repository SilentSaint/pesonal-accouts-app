# Domain Context & Glossary

## Core Concepts

* **Transaction**: An individual financial record representing money spent (debit) or received (credit), featuring amount, currency, timestamp, vendor/merchant, account identifier, and category.
* **Ingestion Source**: The channel through which transaction evidence was received (`SMS`, `Email`, `Manual`, `CSV`).
* **Transaction Event**: A raw raw data payload received from an Ingestion Source before deduplication and reconciliation.
* **Deduplication & Reconciliation**: The domain logic responsible for matching `SMS` and `Email` events. Uses deterministic matching (Card/Account + Amount + Time Window ±15m) for instant auto-merge, flags ambiguous edge cases for 1-tap review, and leverages AI/LLM for unstructured text parsing and smart merchant/category normalization.
* **Bill Statement**: A periodic statement generated by a card issuer or lender (typically ingested via Email) containing total statement balance, minimum due amount, and payment due date.
* **Bill Lifecycle & Auto-Recognition**: Tracking of bill payment states (`PENDING`, `PAID`, `OVERDUE`). Incoming outgoing payment events targeting the card/issuer automatically reconcile against open `Bill Statement` records to mark them `PAID`.
* **Account**: A financial entity (Bank Account, Credit Card, Digital Wallet, Cash) associated with transactions via account identifiers (e.g. last 4 digits).
* **Category & Subcategory**: Hierarchical classification (`Parent > Subcategory`) assigned to transactions automatically via rules/AI or manually.
* **Vendor Mapping & Learning**: The domain logic that remembers user-defined category assignments for raw, ambiguous, or personal payee names (e.g. mapping `saira banu` to `Food & Dining > Tea & Snacks`), automatically applying the learned category to all future transactions matching that payee.
* **Budget**: Target spending limit configured per category or globally per period (e.g. monthly), tracking actual spend against budget threshold.
* **Peer Debt Ledger**: A personal ledger tracking money lent to or borrowed from contacts, allowing single-payment or installment settlements linked to incoming/outgoing transactions.
* **Expense Splitting**: The division of a single transaction among multiple contacts, automatically creating peer debt entries for each contact's share and adjusting the user's net personal expense.
* **Loan & EMI Tracker**: A financial schedule tracking formal loans (principal, interest rate, tenure, EMI due dates) and credit card installment plans, automatically recognizing EMI debits from transaction messages to track remaining balance and progress.



* **AI Financial Insights**: Automated natural language analysis and observations (e.g. spending velocity anomalies, subscription detection, category trend shifts) generated by analyzing transaction history.
* **Financial Analytics & Data Export**: Visual charts (Cash Flow, Category Breakdown, Spending Trends over time) and export capabilities (`CSV`, `PDF`).
* **Email Ingestion Account**: An authenticated email account configured within the app using real-time push notifications (event-driven webhooks). When a financial email or bill statement arrives in the inbox, the email provider instantly notifies the system to extract transaction details without polling. Multiple email accounts can be linked.
* **Serverless Backend Stack**: Java 21 (Quarkus / GraalVM Native) running on AWS Lambda + Amazon DynamoDB + Amazon API Gateway (REST & WebSockets for real-time mobile/web sync).
* **Infrastructure as Code (IaC)**: Terraform HCL configurations used to provision, version, and deploy all cloud resources (Lambda functions, DynamoDB tables, API Gateway endpoints, SNS topics, IAM roles) reproducibly.
* **Access Control**: Device biometric (Fingerprint / Face ID) or 4-digit PIN lock on mobile app resume/open, plus idle session lock on web.
